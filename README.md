# Crystals and Dragons

Консольная игра-лабиринт на Swift. Тестовое задание для вакансии iOS Developer (Sibers).

Герой ходит по лабиринту, ищет ключ и сундук, открывает сундук ключом и получает Грааль.
Если кончаются шаги — герой умирает от голода.

---

## Как запустить

```bash
cd CrystalsAndDragons
swift run crystals      # запустить игру
swift test              # прогнать тесты (25 штук)
```

Проект открывается и в Xcode: `File -> Open... -> папка CrystalsAndDragons` (Xcode сам поймёт Package.swift).
Схема `crystals` — запуск игры, схема с тестами — `Cmd+U`.

Никаких сторонних библиотек: только Foundation и стандартная библиотека Swift.

## Команды в игре

| Команда        | Что делает                                                  |
|----------------|-------------------------------------------------------------|
| `N` `S` `W` `E`| Идти на север / юг / запад / восток (можно и `go north`)     |
| `get [item]`   | Поднять предмет (`get gold` сразу кладёт монеты в кошелёк)   |
| `drop [item]`  | Бросить предмет в комнате                                    |
| `eat [item]`   | Съесть еду и увеличить лимит шагов                           |
| `open chest`   | Открыть сундук — нужен `key`. Это победа                     |
| `fight`        | Атаковать монстра — нужен `sword`                            |
| `look`         | Осмотреться ещё раз                                          |
| `inventory`    | Что я несу                                                   |
| `help`         | Список команд                                                |
| `quit`         | Выйти                                                        |

## Архитектура: MVC + протоколы

Главное требование задания — не сваливать всё в один файл. Поэтому код разбит по ролям:

```
Sources/
├── crystals/            # исполняемое приложение (1 строка кода)
│   └── main.swift
└── GameCore/            # вся логика — отдельная библиотека, её можно тестировать
    ├── Model/           # ДАННЫЕ И ПРАВИЛА (не знают ничего про экран)
    │   ├── Direction.swift   — стороны света
    │   ├── Position.swift    — координаты комнаты
    │   ├── Item.swift        — протокол Item + все предметы
    │   ├── Room.swift        — комната: двери, предметы, монстр, темнота
    │   ├── Monster.swift     — монстр
    │   ├── Player.swift      — игрок: инвентарь, шаги, монеты
    │   └── Maze.swift        — матрица комнат + поиск в ширину (BFS)
    ├── World/           # СОЗДАНИЕ МИРА
    │   ├── MazeGenerator.swift  — генерация проходимого лабиринта
    │   └── WorldPopulator.swift — расстановка предметов, монстров, темноты
    ├── Game/            # CONTROLLER — правила хода игры
    │   ├── Command.swift          — что игрок хочет сделать
    │   ├── CommandParser.swift    — строка -> команда
    │   ├── EncounterResolver.swift— исход встречи с монстром
    │   ├── GameSession.swift      — главный цикл игры
    │   └── GameController.swift   — запуск: спросить размер, создать мир
    ├── View/            # VIEW — всё, что видит игрок
    │   ├── GameView.swift    — протокол «экран»
    │   └── ConsoleView.swift — печать в консоль + цвета
    ├── IO/
    │   ├── InputReader.swift — чтение с клавиатуры (в т.ч. с таймаутом 5 сек)
    │   └── ANSIColor.swift   — цветной текст
    └── CrystalsAndDragons.swift  — сборка всех зависимостей вместе
```

**Правило, которое здесь соблюдается:**

* Model ничего не печатает и не читает ввод — он только хранит состояние и правила.
* View только показывает текст — он не принимает решений.
* Controller (`GameSession`) связывает их: получил команду -> изменил модель -> попросил View показать результат.

Каждый «внешний мир» спрятан за протоколом: `GameView`, `InputReading`, `CommandParsing`,
`MazeGenerating`, `WorldPopulating`, `EncounterResolving`. Благодаря этому в тестах вместо
консоли подставляется `SpyView`, вместо клавиатуры — `ScriptedInput`, а вместо случайности —
`FixedEncounterResolver`. Это и есть **Dependency Injection** и принцип **D** из SOLID
(зависим от абстракций, а не от конкретных классов).

## Как это работает по шагам

1. `main.swift` вызывает `CrystalsAndDragons.run()`.
2. Там создаются все объекты и передаются в `GameController` — это единственное место,
   где кто-то знает конкретные классы (`ConsoleView`, `ConsoleInputReader` и т. д.).
3. `GameController.start()` спрашивает количество комнат и вызывает:
   * `RandomMazeGenerator` — строит лабиринт;
   * `WorldPopulator` — расставляет ключ, сундук, факел, меч, еду, золото, монстров и тьму.
4. `GameSession.run()` крутит цикл:
   ```
   пока игра не закончена:
       если шаги кончились -> проигрыш
       если в комнате живой монстр -> особый ход с таймером 5 секунд
       иначе -> прочитать команду и выполнить её
   ```

### Почему лабиринт всегда проходим

`RandomMazeGenerator` строит лабиринт обходом в глубину (DFS): он выходит из случайной комнаты
и прорубает двери только к ещё не посещённым комнатам. Получается **остовное дерево** —
структура, в которой любая комната связана с любой другой. Изолированных кусков не бывает
в принципе (тест `testMazeIsAlwaysConnected` проверяет это на сотнях лабиринтов).

`WorldPopulator` через поиск в ширину (`Maze.distances(from:)`) считает кратчайший путь
`старт -> ключ -> сундук` и выдаёт лимит шагов = этот путь + запас. То есть выиграть
физически возможно всегда (тест `testStepLimitIsEnoughToReachKeyAndChest`).

### Предметы и полиморфизм

Комната хранит массив `[Item]` — ей не важно, что именно лежит на полу. Особые свойства
описаны протоколами:

* `LightSource` (факел) — освещает тёмную комнату;
* `Edible` (еда) — добавляет шаги;
* `Weapon` (меч) — открывает команду `fight`;
* `Gold` — при `get gold` превращается в монеты, а не в предмет инвентаря;
* `Chest` — единственный предмет с `isPortable == false`.

Чтобы добавить новый тип предмета, достаточно написать одну структуру — код игры менять
не нужно (принцип **O** из SOLID: открыт для расширения, закрыт для изменения).

### Тёмные комнаты

Комната тёмная, если `isDark == true` и при этом:
у игрока нет факела, факел не лежит на полу и комната не была освещена навсегда.
Брошенный в тёмной комнате факел ставит `isPermanentlyLit = true` — комната остаётся
освещённой, даже если факел потом забрать. В темноте разрешено только движение
(`Command.isMovement`).

### Монстры и 5 секунд

`ConsoleInputReader.read(prompt:timeout:)` использует системный вызов `poll()` — он
спрашивает у операционной системы, появились ли данные в stdin, и ждёт не дольше 5 секунд.
Никаких потоков и гонок.

Дальше правила из задания реализует `RandomEncounterResolver`:

| Ситуация                | Результат                                       |
|-------------------------|-------------------------------------------------|
| не успел за 5 секунд    | −10% жизненной силы и отброс в прошлую комнату  |
| успел, 1/3              | −10% и отброс назад, команда не выполняется     |
| успел, 1/3              | команда выполняется, но −10%                    |
| успел, 1/3              | команда выполняется, потерь нет                 |

Если игрок ввёл `fight` и есть меч, «успешное выполнение команды» означает уничтожение монстра.

## Тесты

```bash
swift test
```

* `MazeGeneratorTests` — связность лабиринта, двусторонние двери, 1–4 двери у комнаты.
* `WorldPopulatorTests` — ключ/сундук существуют, достижимы, шагов хватает, критичные комнаты не тёмные.
* `CommandParserTests` — разбор всех команд и мусорного ввода.
* `GameSessionTests` — победа, поражение, темнота, факел, еда, золото, монстр, меч.
